    • Base layer: CloudFront + WAF is the only entry (static web on S3 via OAC, /api/* to the HTTP API, /api/v1/products* cached); Cognito issues JWTs checked by the HTTP API JWT authorizer; each module is one Lambda outside a VPC and one DynamoDB table (ADR-0005, 0006, 0007, 0012).
    • Flow 1 browsing: catalog reads products, recommendation only reads precomputed results from the recs table; events stores VIEW, ADD_TO_CART with an HMAC-hashed userId and rejects PURCHASE from the browser.
    • Flow 2 ordering: one DynamoDB transaction (price check, stock decrement, at most 3 open orders, write PENDING), then SQS; the worker sets CONFIRMED, publishes SNS order-confirmed so events records PURCHASE, sends the SES email; after 3 failures the message goes to the DLQ.
    • Flow 3 nightly recommendations: EventBridge Scheduler at 02:00 invokes a Python Lambda that reads the events and products tables directly (the training-data bucket exists but the pipeline does not use it), it computes also-bought, for-you and bestsellers; a model is switched on only if it beats the baseline, by moving the ACTIVE#<type> pointer.
    • Edges of the diagram: GitHub Actions OIDC + CDK, CloudWatch alarms and runbooks, 3 environments in one account (ADR-0008, 0013). Planned layout: users on the left, CloudFront in the middle, backend on the right, the 3 flows numbered with one colour each.
