shop-ai - Product recommendations (Workshop 5.5)

How shop-ai collects shopping events, builds three kinds of recommendations every night and serves them to the web. Press a numbered flow to walk its arrows; click a component for its role.

The nightly job also mixes in synthetic events while real traffic is small; the CloudWatch alarm exists in prod only.

Flow steps
  1. Web request. The browser calls /api/* through CloudFront to the HTTP API.
  2. Track events. Lambda events stores VIEW and ADD_TO_CART events with the user id hashed by the HMAC key from SSM.
  3. Purchase events. order-confirmed from SNS reaches the events-purchase queue; its Lambda writes PURCHASE events.
  4. Nightly pipeline. At 02:00 EventBridge Scheduler runs recs-pipeline: it reads events and products, builds also-bought, for-you and bestsellers, writes a new version and switches ACTIVE only when it beats the baseline.
  5. Serve recommendations. Lambda recs reads the ACTIVE version for the home page, the product page and for-you (signed-in users, hashed id).
  6. Watchdog. CloudWatch alarms in prod when the pipeline has not succeeded.
